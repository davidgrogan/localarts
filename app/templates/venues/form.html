Squarespace sites render their own content with JS, so a plain HTML scrape often comes back empty — the Squarespace option uses the site's own ?format=json page-data endpoint instead. That only works if the events are actually stored in Squarespace's own collection, though: some venues (the Iron Horse included) embed a third-party calendar widget (e.g. Elfsight) that has its own private data source Squarespace's JSON never sees. If that widget is specifically Elfsight's "Event Calendar", use "Elfsight widget (JSON-LD)" — each event card embeds a full schema.org Event script tag (name, dates with year, description, location) that's far more reliable than scraping the widget's visible markup, which uses hashed class names and never shows a year in the date text. Use "Headless browser" for other JS-rendered widgets without that JSON-LD, and "Generic HTML" for plain server-rendered pages with no JS involved.
item_selector / title_selector / date_selector / optional date_format / optional link_selector apply to both HTML source types. wait_for_selector and wait_ms apply to both "Headless browser" and "Elfsight widget" — use the browser's Inspect tool on a rendered event card to find real class names/selectors once you can see the widget on screen. "Elfsight widget" ignores the selector keys and instead takes optional location_match (a list of substrings matched case-insensitively against each event's JSON-LD location name, since one Elfsight feed can cover several physical venues — defaults to this venue's own name) and optional include_all_locations (true to skip that filtering and import every event on the feed).
